# 트러블슈팅: 관찰에서 제어·구조 변경까지

[English](../troubleshooting.md) | 한국어

이 프로젝트에서 바퀴의 비정상 움직임과 전도는 하나의 원인으로 설명되지 않았다. RC 입력, 모터 구동, 자세 기준, 속도 피드백, ROS 명령 경로를 나누어 확인하면서 제어와 시험 방법을 바꿨다.

각 사례는 **문제 상황 → 조사한 경로 → 실제 대응 → 판단의 변화 → 확인 가능한 결과**를 연결한다. 중요 사례는 안전과 실물 동작에 직접 영향을 준 조사이며, 보조 사례는 그 과정을 이해하는 데 필요한 센서·피드백·소프트웨어 설계다.

| 사례 | 수행한 작업 | 면접관이 확인할 근거 |

**짧게 검토한다면:** 사례의 첫 문단으로 결과를 확인하고, 관찰 표 또는 시험 사진을 본 뒤 코드 발췌와 최종 근거 링크를 따라가면 된다.

## 근거의 범위

테스터 출력 열과 코드 발췌는 저장소 구현을 보여준다. 사진과 짧은 영상은 시험 환경과 동작을 보여준다. 금속·포일 실험 및 펌웨어 다운그레이드 결과는 기존 작업 기록에 근거하며, 공개된 원시 실험 로그는 없다. 코드에서 계산한 값은 실측값과 구분해 표시했다.

저장소는 원래 프로젝트를 복원·정리한 포트폴리오다. 테스터가 존재한다는 사실만으로 모든 역사적 시험 결과가 입증되는 것은 아니다. 각 문서는 현재 확인할 수 있는 작업과 결과를 중심으로 읽도록 구성했다.

전체 수식은 [제어 알고리즘](../../firmware/physical_balance_controller/control_algorithm.md), 프로젝트의 완료 범위는 [결과와 한계](results-and-limitations.md), 시뮬레이션과 실물의 연결은 [Sim2Real](sim2real.md)에서 확인할 수 있다.
