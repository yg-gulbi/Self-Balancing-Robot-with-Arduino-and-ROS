# IMU 캘리브레이션과 직립 기준

[English](../../../troubleshooting/supporting/01-imu-upright-reference.md) | [트러블슈팅 목차](../../troubleshooting.md)

**분류:** 보조 이슈 · 기존 문서와 코드에서 재구성한 기록

## 1. 문제정의

센서의 0°와 실제 로봇의 직립 자세가 다르면 계속 보정하거나 서서히 이동할 수 있다. 장착 오차와 캘리브레이션 상태를 고려해야 한다. 기존 문서에 문제 설명은 있지만 이 현상만 분리한 드리프트 데이터는 없다.

## 2. 해결방법 안들 설정

BNO055 감지와 캘리브레이션 상태를 확인하고 센서 자체 보정과 장착·직립 오프셋을 구분한다. 재시작 재현성을 위해 EEPROM 저장·복원을 검토하되 실제 자동 복원이 활성화되어 있는지 확인한다.

## 3. 해결방법 실행

최종 코드에는 BNO055 초기화 실패 시 정지, 캘리브레이션 저장·복원 함수, 상태 확인 기능이 있다. 자세 계산에는 `imu_angle_offset=3.5`를 사용한다. 시작 시 `loadCalibration()` 호출은 주석 처리되어 있으므로 부팅마다 보정값을 자동 복원한다고 설명할 수 없다.

## 4. 경험의 재해석

직립은 센서 장착과 로봇 기구에 맞춰 정해야 하는 운용 기준이다. 보정 함수의 존재, 부팅 시 실제 실행 여부, 적절한 직립 오프셋은 각각 구분해서 확인해야 한다.

## 5. 정리

결과：각도 오프셋 보정은 적용되어 있고 EEPROM 함수는 존재하지만 시작 시 자동 복원은 비활성 상태다. `setup()`, `saveCalibration()`, `loadCalibration()`과 각도 계산을 확인한다. 재시작 검증에는 동일한 물리 자세에서 보정 상태와 출력 각도를 기록한다.
