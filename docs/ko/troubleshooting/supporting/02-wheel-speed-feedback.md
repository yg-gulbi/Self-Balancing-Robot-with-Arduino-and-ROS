# 바퀴 속도 피드백과 시리얼 수신 신뢰도

[English](../../../troubleshooting/supporting/02-wheel-speed-feedback.md) | [트러블슈팅 목차](../../troubleshooting.md)

**분류:** 보조 이슈 · 기존 문서와 코드에서 재구성한 기록

## 1. 문제정의

바퀴 속도 샘플이 튀면 양쪽 모터에 들어가는 속도 보정값이 왜곡될 수 있다. 기존 기록에는 비현실적인 변화와 파싱 문제가 설명되지만 최종 코드만으로 발생 빈도를 알 수는 없다.

## 2. 해결방법 안들 설정

원시 시리얼 응답과 파싱한 속도를 비교하고 바퀴 방향 부호와 선속도 변환을 확인한다. 과거 이력 기반 이상치 제거, 중앙값 계열 대체, 평활화를 검토하되 지연도 고려한다. 과거 실험 코드와 최종 적용 코드를 구분한다.

## 3. 해결방법 실행

기존 문서는 보관된 펌웨어의 적응형 임계값·중앙값 계열 대체 처리를 설명한다. 최종 코드는 `parseFloat()` 읽기 전후 현재 수신된 바이트를 비우고 바퀴 방향·반지름으로 속도를 변환하며 속도 적분과 출력을 제한한다. 다만 `kAlpha_3=1`이므로 새 샘플을 그대로 사용해 실제 평활화는 비활성이다. 수신 바이트를 비우는 처리만으로 응답 프레임의 완전성이나 유효성을 보장하지는 못한다.

## 4. 경험의 재해석

변수명에 filtered가 있어도 필터가 활성이라는 뜻은 아니다. 피드백 값의 유효성과 수신 시간도 안정성에 영향을 준다. 과거 이상치 처리 실험을 현재 코드의 보호 기능으로 설명하려면 실제 적용 여부를 확인해야 한다.

## 5. 정리

결과：수신 버퍼 정리와 속도 보정 제한은 존재하지만 활성 속도 평활화와 완전한 샘플 검증은 확인되지 않는다. `BalanceController()`와 보관 펌웨어를 검토한다. 후속 검증에는 원시 응답, 파싱 시간·타임아웃, 샘플 지연, 속도 급변을 동일 시험 조건에서 기록한다.
