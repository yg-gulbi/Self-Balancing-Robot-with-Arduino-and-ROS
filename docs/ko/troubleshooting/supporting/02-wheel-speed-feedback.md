# 속도 값이 튀면 모터 보정도 튄다: 피드백 처리의 변화

[English](../../../troubleshooting/supporting/02-wheel-speed-feedback.md) | [전체 트러블슈팅](../../troubleshooting.md)

> 과거 코드에서는 최근 값과 중앙값으로 급변 샘플을 처리했고, 최종 코드에서는 수신·파싱과 속도 보정 제한을 사용한다. 과거 실험과 현재 활성 처리를 구분해 읽을 수 있다.

## 속도 피드백의 이상이 자세 제어까지 영향을 주는 경로

속도 루프는 목표 속도에서 좌우 바퀴 평균 속도를 빼 보정값을 계산한다. 이 값은 두 모터에 공통으로 들어간다. 따라서 속도 샘플 하나가 비정상적으로 변해도 조작 입력이 바뀐 것처럼 보정값이 달라질 수 있다.

이 문제는 바퀴 속도를 출력해 보기만 하는 문제가 아니라 **어떤 샘플을 제어에 사용할 것인가**의 문제였다.

## 과거 코드에서는 최근 샘플과 비교했다

[legacy 제어기](../../../../archive/arduino_firmware/legacy_balance_controller.ino)에는 최근 5개 값의 절댓값 평균을 이용하는 임계값 함수가 있다.

```cpp
return 3.0 * (sum / N);
```

새 값과 직전 값의 차이가 이 임계값을 넘으면 이전 두 값과 새 값의 중앙값을 사용한다.

```cpp
if (abs(phi_dot_counts_0 - prev_dot_0) > adaptive_threshold_dot_0) {
    phi_dot_counts_0 = median_phi_dot_0;
}
```

즉 단일 고정 한계만 비교하기보다 최근 값의 크기를 반영하고, 급변 샘플의 영향을 중앙값으로 줄이는 방식을 실험했다. 다만 임계값 계산 이력에도 새 값이 들어가므로 이를 검증된 통계적 이상치 판별기라고 확대해 설명하지 않는다.

## 최종 코드를 보면 남은 처리와 빠진 처리가 보인다

| 경로 | 과거 코드 | 최종 코드 |
| --- | --- | --- |
| 급변 값 처리 | 최근 이력 임계값과 3개 값 중앙값 | 동일한 경로는 활성 루프에 없음 |
| 수신 처리 | 위치·속도 값 확인 경로 | 읽기 전후 현재 수신 바이트 비우기, `parseFloat()` 2회 |
| 속도 평활화 | 과거 처리식과 계수 사용 | 평활화 식은 있으나 `kAlpha_3=1` |
| 제어 영향 제한 | 과거 제어 설정 | 속도 적분 ±5, 보정 출력 ±6 |

최종 코드의 평활화 식에 현재 계수를 넣으면 새 값이 그대로 통과한다. 변수명이 `filtered_phi_dot`여도 이 설정에서는 속도 평활화가 작동하지 않는다.

또한 최종 파일에 `filterEncoderData()`라는 보조 함수가 남아 있지만 활성 `BalanceController()`에서 호출하지 않는다. 함수 존재와 실제 제어 경로 적용은 구분해야 한다. 수신 버퍼 정리도 응답의 길이·샘플 유효성·타임아웃을 검증하는 완전한 프레임 파서는 아니다.

## 피드백 품질과 출력 제한을 별개로 보게 되었다

적분과 출력 제한은 비정상 샘플이 만든 보정의 크기를 제한한다. 반면 이상치 판별은 입력 샘플 자체를 판단한다. 두 방식은 역할이 다르며, 어느 하나가 있다고 다른 하나를 수행한다고 볼 수 없다.

과거·최종 코드를 나란히 비교하면 이상치 처리 실험은 확인할 수 있지만, 그 실험이 최종 코드에 전부 적용되었다는 설명은 맞지 않는다.

## 관련 코드와 기록

- [legacy_balance_controller.ino](../../../../archive/arduino_firmware/legacy_balance_controller.ino): `updateThreshold()`, `getMedian()`, 급변 값 대체.
- [최종 제어기](../../../../firmware/physical_balance_controller/physical_balance_controller.ino): 수신·파싱, `kAlpha_3`, 속도 보정 제한.

공개 코드로 처리 방식의 변화를 확인할 수 있다. 원시 시리얼 응답과 속도·전류 요청을 함께 기록한 전후 로그는 없어, 필터 적용에 따른 진동 감소량까지 제시하지 않는다.
